# Touch Schatzi for iOS (iPhone + iPad)

A native iOS app (Swift / UIKit, iOS 16+) that hosts the **same game the Android app ships**. The game itself
(rules, AI, art, sound, UI, characters, banter) is the web bundle in
[`../app/src/main/assets/www`](../app/src/main/assets/www). The Xcode project references that folder directly,
so Android and iOS can never drift apart: change the game once, both apps get it.

> **Status:** first build. Written and reviewed on Linux; it is compiled, unit-tested and launched in the iOS
> Simulator by the **iOS build** GitHub workflow. It has **not** yet been run on a physical iPhone and has **not**
> been signed. See [Not yet verified](#not-yet-verified).

## What is in the app

Everything the Android app does, with the same behaviour:

| Area | Behaviour (same as Android) | iOS notes |
|---|---|---|
| First launch | Branded splash with "Touch to play", music starts on first touch | Native launch screen (brand purple + cat logo) fades into the splash, no white flash or "Loading…" text |
| Menu | Choose 0-3 opponents (Lily, Scoobert, Max), difficulty, name, Music / Sound FX / Trash talk / Hints, How to Play | Compact layouts for iPhone SE-size screens, scaled layout on iPad; name field never triggers iOS zoom |
| Game | Slot-machine dice, hold, 3 spins, score card sheet, 13 rounds, AI opponents with trash talk, hints, fast opponents | Layout verified at iPhone SE, iPhone 15 Pro, iPad, portrait and landscape, with notch/Dynamic Island and home-indicator safe areas |
| Pause | Pause button, Resume / Restart / Quit, option toggles | Also pauses automatically when you leave the app, lock the phone, or a call/Siri interrupts (replaces Android's pause on `onPause`) |
| Results | Win / lose screens with confetti, ranking, best score, Play Again | unchanged |
| Settings & best score | Stored on device | Mirrored natively so iOS clearing web storage can't wipe the player's name, options or best score |
| Haptics | Android `Vibrator` | Core Haptics (iPhone 8+), new **Haptics** on/off toggle in the pause menu; hidden on iPad (no Taptic Engine) |
| Sound | Synthesized Web Audio engine | Follows the silent switch, mixes with the player's own music, resumes after interruptions |
| Permissions / network | Only `VIBRATE`; fully offline | **None.** No network, no tracking, no analytics, no accounts |
| Error state | `Failed to start` text | Branded "couldn't start" screen with **Try Again**, boot watchdog, and automatic recovery if iOS kills the web process |
| Android back button | Closes the score card / toggles pause | Not applicable on iOS: use the on-screen pause button (the score card closes by swipe/tap as before) |

### How the native shell works

* **Offline origin.** `AssetSchemeHandler` serves the bundled `www/` through `touchschatzi://localhost/...`
  (the iOS equivalent of Android's virtual `https://appassets.androidplatform.net`). A real origin is what lets ES modules
  and `fetch()` work offline. Paths are sanitised so nothing outside `www/` can ever be served; the web view refuses to
  navigate anywhere else.
* **Bridge.** The web layer talks to the app through three `webkit.messageHandlers` (`haptics`, `nativeStore`, `appState`),
  accepted only from our own page. In a browser or on Android they are simply absent and ignored.
  `js/lib/haptics.js` picks iOS → Android → Vibration API automatically.
* **Lifecycle.** The app calls the game's existing `TS.setPaused()` hook (the same one Android uses) when it resigns
  active/becomes active, and on audio interruptions.
* **Full screen.** Status bar hidden, home indicator auto-hides, bottom-edge system gesture is deferred so dragging up the
  score card does not leave the app, screen stays awake while playing (like Android's `FLAG_KEEP_SCREEN_ON`),
  the web view resizes above the keyboard (like Android's `adjustResize`).

## Shared-code changes (safe for Android)

Small, additive edits to `www/`; the Android app behaves as before:

* `js/lib/haptics.js`: iOS bridge, `supported()` capability check.
* `js/main.js`: audio unlock also on `touchend`/`click` (iOS Safari does not unlock audio on `touchstart`), the saved
  haptics preference is applied at boot, `ready`/`error` signals for the native shell.
* `js/game/screens/play.js`: Haptics toggle in the pause menu (shown only where haptics exist).
* `js/game/screens/menu.js`: name field attributes (no autocorrect, Done key).
* `css/main.css`: `-webkit-` prefixes, `-webkit-touch-callout`, 16 px minimum for the name input on iOS, compact menu
  for short phones (PLAY was off-screen on a 375×667 iPhone SE and on 360×640 Androids), scaled menu on tablets.

## Decisions and assumptions (information the repo did not contain)

| Topic | Choice | Why / how to change |
|---|---|---|
| Bundle identifier | `com.touchschatzi.game` (same as Android `applicationId`) | No iOS identifier existed. Change `BUNDLE_ID` in `tools/gen_xcodeproj.py` if it is taken in your Apple account. |
| Team / signing | Automatic signing, **no team set** | No Apple Developer details in the repo. Pick your Team in Xcode (Signing & Capabilities) or pass the Team ID to `archive_for_testflight.sh`. |
| Version | `1.0.0` (build `1`) | Matches Android `versionName`. Bump `BUILD_NUMBER` for every TestFlight upload (the script does this automatically). |
| Minimum iOS | **16.0** (iPhone 8 and later) | Guarantees Core Haptics hardware, avoids tiny 320 pt screens, and 16+ covers essentially all active devices. |
| Devices | iPhone **and** iPad, portrait + landscape (iPad: all four) | Android allows rotation (`fullUser`); the game's layout already supports both. Mac "Designed for iPad" and Vision are switched off for the first release. |
| App icon | Generated by `tools/make_icons.py` from the repo's own cat artwork (`chars/cat.webp`): cat in a gold ring on brand purple, as on Android | The Android icon is only 432 px; this builds a true 1024 px opaque icon. Replace `AppIcon-1024.png` if you have final marketing art. |
| Fonts | System fonts, as on Android | The CSS expects optional `assets/fonts/display.*` / `body.*` that are not in the repo. iOS falls back to Arial Rounded MT Bold (display) and the system font (body). Drop the files in to override on both platforms. |
| Audio | Silent switch is respected; mixes with other apps' audio (`.ambient`) | Standard for casual games. Change in `AudioSessionController` if you want music to override the switch. |
| Language | English only | The game text is English in the shared web code. |
| Privacy | `PrivacyInfo.xcprivacy`: no tracking, no data collected; declares UserDefaults use (reason CA92.1) | The app has no network access at all. `ITSAppUsesNonExemptEncryption = NO`. |
| Age rating | **Needs your answer in App Store Connect** | The game has slot-machine styled dice. Answer the "simulated gambling" question honestly (no real money, no prizes); it may affect the rating. |
| Store listing | Not in the repo | Screenshots, description, support URL and a **privacy policy URL** are needed for App Store / external TestFlight (not for internal testers). See `TESTFLIGHT.md`. |

## Build, run, test

On a Mac with Xcode 16+:

```bash
open touch-schatzi/ios/TouchSchatzi.xcodeproj      # pick a simulator, press Run
```

```bash
xcodebuild test -project touch-schatzi/ios/TouchSchatzi.xcodeproj -scheme TouchSchatzi \
  -destination 'platform=iOS Simulator,name=iPhone 16' CODE_SIGNING_ALLOWED=NO
```

Debug builds accept a launch argument to jump to a screen (used by CI screenshots):
`-TSStartQuery "screen=play&opp=lily,scoobert,max&diff=hard"` (also `screen=menu`).

Regenerate generated files (both are committed; CI fails if the project is out of sync):

```bash
python3 touch-schatzi/ios/tools/gen_xcodeproj.py    # after adding/removing Swift files
python3 touch-schatzi/ios/tools/make_icons.py       # needs Pillow
```

Web-only changes can be tried in a browser: `cd touch-schatzi/app/src/main/assets/www && python3 -m http.server 8765`.

## CI

`.github/workflows/ios-build.yml` ("iOS build", macOS runner) runs on `claude/**` pushes that touch the iOS project or
the shared game: web rules tests, project-in-sync check, **unit tests in the iOS Simulator**, **launches the real app on an iPhone and
an iPad simulator and screenshots splash/menu/game**, then an **unsigned Release device build** (checks the bundle
contains the game, asset catalog and privacy manifest). Artifacts: simulator screenshots and an unsigned `.ipa`
(for inspection only: it cannot be installed on a device until signed). The existing Android AutoBuild is untouched.

## Not yet verified

Be aware of what has **not** been proven yet:

* Running on a **physical** iPhone/iPad: haptic feel, audio output through the speaker and the silent switch, keyboard
  behaviour, performance on older devices.
* **Signing, archive and App Store Connect validation** (needs your Apple Developer account).
* Landscape and rotation inside the simulator (CI screenshots are portrait); the layout was verified in a browser at
  iPhone/iPad landscape sizes with simulated safe areas.
* Accessibility (VoiceOver): the game is canvas/DOM art; native screens have labels, the game board does not.
